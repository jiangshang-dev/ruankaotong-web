# 软考通 — 技术说明与打包指南

软考通是一款**本地优先**的软考备考笔记桌面应用：无需登录，笔记按学科保存为 Markdown，可选接入本地 AI 服务做论文润色与评分。

---

## 一、用了哪些技术

### 1. 桌面壳与工程

| 技术 | 用途 |
|------|------|
| **Electron** | 跨平台桌面壳（主进程 + 渲染进程） |
| **electron-vite** | 主进程 / preload / 渲染进程一体构建与热更新 |
| **electron-builder** | 打 Mac DMG、Windows 安装包 / 便携包 |
| **TypeScript** | 主进程与前端统一类型约束 |
| **Node.js `fs`** | 本地读写 Markdown、图片、排序配置 |

### 2. 前端

| 技术 | 用途 |
|------|------|
| **Vue 3**（`<script setup>`） | UI 与交互 |
| **Vue Router** | 页面路由（当前以工作区为主） |
| **Pinia** | 全局状态（目录、学科、笔记列表、当前文件） |
| **Vite + `@vitejs/plugin-vue`** | 渲染进程打包 |
| **原生 HTML5 Drag & Drop** | 笔记列表拖动排序（未引入第三方拖拽库） |
| **`contenteditable` + `document.execCommand`** | 知识点富文本编辑 |

### 3. Markdown 与媒体

| 技术 | 用途 |
|------|------|
| **marked** | Markdown → HTML（打开笔记回显） |
| **turndown** | HTML → Markdown（保存时落盘） |

### 4. 进程通信与安全

| 技术 | 用途 |
|------|------|
| **IPC**（`ipcMain` / `ipcRenderer.invoke`） | 渲染进程请求主进程读写文件、选目录等 |
| **preload + `contextBridge`** | 向页面暴露受控 `window.api`，避免直接开放 Node |

### 5. AI（可选，独立后端）

论文「润色 / 评分」通过 HTTP 调用本地后端（默认 `http://127.0.0.1:9001`），由环境变量 `VITE_AI_BASE_URL` 配置。后端可使用 **Spring Boot + AgentScope** 等实现，与桌面端解耦；不启动后端时，笔记读写与打包功能仍可独立使用。

## 二、项目结构（简要）

```text
ruankaotong/
├── src/
│   ├── main/                 # Electron 主进程
│   │   ├── index.ts          # 窗口创建、IPC 注册
│   │   └── fs-service.ts     # 本地目录 / 笔记 / 图片 / 排序

│   └── renderer/src/         # Vue 前端
│       ├── views/            # WorkspaceView 三栏工作区

│       ├── utils/            # exam 字数与 Markdown 组装、markdown 转换
│       ├── api/essayAi.ts    # AI 润色 / 评分 HTTP 客户端
│       └── data/subjects.ts  # 学科列表
├── docs/说明.md              # 本文档
├── electron.vite.config.ts
├── package.json              # scripts 与 electron-builder 配置
└── release/                  # 打包产物目录（构建后生成）
```

## 三、功能如何实现

### 1. 无登录 + 本地目录仓库

- 用户通过系统对话框选择根目录；路径写入 Electron `userData` 下的 `ruankaotong-config.json`。
- 切换学科时，主进程 `ensureSubjectDirs` 自动创建：

```text
根目录/
  {subjectId}/
    notes/           # 知识点 .md
    notes/assets/    # 笔记截图
    notes/.order.json
    essays/
    essays/assets/
    essays/.order.json
```

- 学科定义在 `src/renderer/src/data/subjects.ts`（架构、高项、软设、网工等）。

### 2. 知识点笔记

- **编辑**：`MarkdownRichEditor` 使用 `contenteditable` + 工具栏（H1–H3、字号、加粗/斜体/下划线、对齐、列表、引用等）。
- **落盘**：保存时 `htmlToMarkdown`（turndown）转成 Markdown；标题只写 YAML frontmatter，正文不再重复插入 `# 标题`（避免多次保存叠标题）。
- **打开**：`markdownToHtml`（marked）回显；空正文用单个 `<br>`，避免 Chrome 把光标落到「第二行」。
- **截图**：粘贴 / 拖拽图片经 IPC `notes:saveImage` 存到 `notes/assets/`，Markdown 中引用相对路径；打开时读成 data URL 显示。
- **图片缩放**：选中图片后可拖拽手柄或按 25%/50%/75%/100%/原大调整宽度，宽度写入 HTML/`data-width`，再经 turndown 保留。

### 3. 论文练习

- **结构**：题目（首行作题目名）、摘要（≤300 字）、正文，分块编辑并按 `## 题目描述 / 摘要 / 正文` 等约定组装进 Markdown。
- **字数**：`countExamWords` 按软考习惯统计——汉字 1 字、英文/数字整词 1 字、标点 1 字。
- **清理**：打开 / 保存 / AI 润色后做分段消毒，避免题目、摘要框内容串进正文。

### 4. 列表拖动排序

- 中间栏使用原生 `draggable`，拖动时 Pinia `moveNote` 即时重排。
- 松手后 IPC `notes:saveOrder` 把文件名顺序写入对应目录的 `.order.json`。
- `listNotes` 按该文件排序；未出现在排序表中的文件按修改时间补在后面。
- 新建文件默认插到顺序最前；删除 / 重命名会同步维护排序表。

### 5. AI 润色与评分（可选）

- 前端 `api/essayAi.ts`：`POST /api/ai/essay/polish`、`POST /api/ai/essay/score`。
- 开发环境可在 `.env.development` 中设置：

```bash
VITE_AI_BASE_URL=http://127.0.0.1:9001
```

- 未配置时默认连本机 `9001` 端口；后端需自行启动。

### 6. 界面布局

- 三栏：学科侧栏 / 笔记列表 / 编辑区。
- 整体页面不滚动；学科列表、笔记列表、编辑区各自独立滚动。

### 7. IPC 能力一览（`window.api`）

| API | 作用 |
|-----|------|
| `getConfig` / `saveConfig` | 读写本地配置 |
| `selectDirectory` | 选择仓库目录 |
| `ensureSubject` | 创建科目目录 |
| `listNotes` / `readNote` / `writeNote` / `deleteNote` / `renameNote` | 笔记 CRUD |
| `saveNotesOrder` | 持久化拖动排序 |
| `saveImage` / `readImageDataUrl` | 截图存取 |
| `openPath` | 在访达 / 资源管理器中打开目录 |

## 四、本地开发

环境要求：Node.js 18+（建议 LTS），已安装 npm。

```bash
cd /path/to/ruankaotong
npm install
npm run dev
```

常用脚本：

| 命令 | 说明 |
|------|------|
| `npm run dev` | 开发模式启动 Electron |
| `npm run typecheck` | 主进程 + 渲染进程类型检查 |
| `npm run build` | 仅构建到 `out/`（不打安装包） |

如需 AI 功能，先启动对应后端，再确认 `VITE_AI_BASE_URL` 指向正确地址。

## 五、如何打包

`package.json` 中已配置 **electron-builder**：

- 应用名：`软考通`
- appId：`com.ruankaotong.app`
- 产物目录：`release/`
- 打包内容：`out/**/*`（先由 electron-vite `build` 生成）

### 1. 打包 Mac DMG

在 **macOS** 上执行：

```bash
npm run dist:mac
```

等价于：先 `npm run build`，再 `electron-builder --mac dmg`。

成功后大致得到：

```text
release/
  软考通-1.0.0.dmg          # 可分发的磁盘映像
  mac/ 或 mac-arm64/ 等     # 未压缩的 .app（架构因本机而异）
```

说明：

- 在 Apple Silicon（M 系列）本机打包，默认多为 **arm64**；在 Intel Mac 上多为 **x64**。
- 若要同时打通用包或指定架构，可按需扩展 electron-builder 的 `mac.arch` / `universal` 配置。
- **未配置苹果开发者签名 / 公证**时，其他用户首次打开可能提示「无法验证开发者」，需在「系统设置 → 隐私与安全性」中允许，或右键「打开」。
- 正式分发建议配置 `CSC_LINK` / 公证（notary）等，本文不展开。

### 2. 打包 Windows exe

在 **Windows** 上执行（推荐）：

```bash
npm run dist:win
```

等价于：先 `npm run build`，再 `electron-builder --win nsis portable`，会生成两类产物：

| 类型 | 说明 |
|------|------|
| **NSIS** | 传统安装程序（`.exe` 安装向导） |
| **portable** | 便携版（解压即用 / 单文件便携，具体以 builder 输出为准） |

产物一般在：

```text
release/
  软考通 Setup 1.0.0.exe    # NSIS 安装包（名称以实际输出为准）
  软考通 1.0.0.exe          # 便携包（名称以实际输出为准）
  win-unpacked/             # 未打包目录，便于调试
```

说明：

- **在 Mac 上交叉编译 Windows** 往往需要额外工具链（如 Wine），容易踩坑；**建议在 Windows 机器或 Windows CI 上打 Windows 包**。
- Windows 包默认也**未做代码签名**，SmartScreen 可能拦截，正式发布需购买证书签名。

### 3. 通用打包命令

```bash
# 按当前系统默认目标打包
npm run dist

# 仅编译，不调用 electron-builder
npm run build
```

### 4. 打包前检查清单

1. `npm run typecheck` 通过。
2. `npm run dev` 手动点一遍：选目录、新建笔记、保存、拖排序、论文计字。
3. 若发行版需要 AI：确认构建时写入的 `VITE_AI_BASE_URL` 指向用户环境可达的地址（生产可用 `.env.production`）。
4. 清理旧产物（可选）：删除 `release/` 后再打，避免混淆版本。

## 六、配置摘要（electron-builder）

摘自 `package.json` 的 `build` 字段：

```json
{
  "appId": "com.ruankaotong.app",
  "productName": "软考通",
  "directories": { "output": "release" },
  "files": ["out/**/*"],
  "mac": {
    "target": ["dmg"],
    "category": "public.app-category.education"
  },
  "win": {
    "target": ["nsis", "portable"]
  }
}
```

修改版本号：改 `package.json` 的 `"version"`，再重新执行对应 `dist:*` 命令。

## 七、使用与数据约定

- 应用**不上传**笔记内容；数据只存在用户选择的本地文件夹。
- 可用任意 Markdown 编辑器直接打开仓库中的 `.md` 文件；拖动排序依赖同目录下的 `.order.json`，勿随意删改除非理解其格式（JSON 字符串数组，元素为文件名）。
- 删除应用不会自动删除用户笔记目录；卸载安装包与删除仓库目录是两件事。
